## GUI Intl 的具体挂点

推荐在固定 GUI 的 `src/lib/connected-intl-provider.jsx` 中，仅把 `mapStateToProps` 返回的 `messages: state.locales.messages` 接至外部 `window.CFZNOpenBlock.brandMessages(messages, locale)`，无适配器时走原值。该函数在应用创建 GUI 前由当前外部桥提供，读取 render 时的实际 locale。这里同时覆盖菜单、连接、WebGL、异常及 TitledHOC 默认项目名。保留 `key: state.locales.locale` 及现有 locale 生命周期，以原 messages 对象与 locale 缓存派生结果，避免每次 Redux 更新重建消息对象。 [统一 Intl 入口](../../.runtime/web-openblock/openblock-vendor/openblock-gui.js#L338725) · [现有外部桥安装](../../apps/web/src/openblock.ts#L448)

适配函数只处理审核过的 GUI 消息 ID，保留消息插值及其他翻译。先合入对应语言的品牌词值，未提供对应翻译时使用经过审核的英文品牌消息。对于现有非英文文案，仅在这些 ID 的产品名称片段调整 OpenBlock→CCraft。以下为本次实际发现的消息清单。

- `gui.alerts.lostPeripheralConnection`。
- `gui.unsupportedBrowser.notRecommended`、`gui.unsupportedBrowser.description`。
- `gui.connection.unavailable.installscratchlink`。使用“请确认与当前设备兼容的本机连接服务已安装并运行”等准确文案，避免凭品牌替换承诺已有 CCraft Link 私有协议实现。
- `gui.crashMessage.description`。改为“CCraft 编辑器遇到问题，请刷新后重试”等当前真实行为，保留独立错误编号展示。自动上报的承诺以实际启用能力为准，当前应用设置 `isTelemetryEnabled:false`。
- `gui.webglModal.description`。
- `gui.gui.defaultProjectTitle`。
- `gui.telemetryOptIn.label/body1/optInText/optOutText`。这组属于未启用的原生弹窗消息，品牌覆盖需一致，并继续沿既有关闭状态运行。

这些 ID 的命名保持原值。语言覆盖应包含当前可选 locale，尤其简中、繁中、英文及切换后的重挂。实际渲染可能使用缺失翻译时的 defaultMessage，品牌适配应明确补齐上述默认消息。若崩溃边界位于 Intl 外层，可对 `src/components/crash-message/crash-message.jsx` 的 fallback 文案追加 GUI src 精确 hook。上游 reducer 在 bundle 装载阶段初始化，早于外部桥赋值，直接在 reducer initialState 依赖桥容易漏掉首次显示。使用 connected Intl 的运行时入口可覆盖首次 GUI render。

## 自动生成代码与用户数据

当前 `Blockly.Arduino.finish` 输出精确首行 `// generated by OpenBlock\n`，Python 对应 `# generated by OpenBlock\n`，二者都属于受保护的 Blockly 模块。当前应用自动代码由 `ModeController.generate` 调 `Blockly.Arduino.workspaceToCode` 后写入原生代码栏。按主控规则在这个外部出口，对精确起始行替换为 `// generated by CCraft\n`，随后更新 generatedSource。显示、手动模式首次复制、编译代码快照使用同一结果。以 startsWith/首行完整相等为条件，覆盖按实际返回值确认的换行形式。 [外部生成入口](../../apps/web/src/mode-controller.ts#L31) · [上游生成首行](../../.runtime/web-openblock/openblock-vendor/openblock-gui.js#L316920)

程序中其他字符串、注释、手动源码和归档内容保留作者原文。设备描述中的 `Hello OpenBlock` 是串口打印默认字符串数据，已有块中的该值也属于作品内容。新建默认项目名的品牌变化只影响今后新建及空名称兜底，已有保存作品、导入标题和素材采用现有恢复规则。Python 生成首行作为已识别的显示入口记录，若以后启用原生 Python 可见代码路径，再在该外部展示出口精确处理。

## 兼容、署名与聚焦验收

协议 `cfzn.openblock`、MIME `application/x.openblock.ob`、`.ob/.sb3`、`openblock.html`、`/openblock-vendor/`、包名、`CFZNOpenBlock`、DOM/CSS 兼容名称和现有 opcode 都属于技术接口。变更采用应用文案与精确 GUI src 挂点。固定 VM、Blockly 模块按既有工具逐字节核对。第三方 LICENSE、TRADEMARK、源码版权注释及对应来源记录完整保留，实际引用的第三方帮助资料维持正确来源。 [协议](../../apps/web/src/editor-protocol.ts#L1) · [上游边界检查](../../apps/web/scripts/verify-upstream-bytes.mjs) · [GUI 挂点约束](../../apps/web/scripts/openblock-hooks.mjs#L375)

建议独立 dev/dist 聚焦验证以下内容。

1. 启动遮罩、两个浏览器标题、iframe 可访问名称、本地 favicon 和顶栏正常/overflow 字标均为 CCraft。断网仍能加载品牌资源，Logo 尺寸和菜单布局符合当前规则，全屏舞台品牌分支一并核对。
2. 新建默认名、空导出名及恢复文件名含 CCraft。新页打开旧作品后标题、积木字符串、声音和造型保持，手写包含 OpenBlock 的源码逐字符一致。
3. 中文、繁中与英文切换后，断连、WebGL、启动超时和 GUI fallback/crash 等受控消息不再显示旧产品品牌，插值设备名和错误详情正常。逐项匹配消息 ID，避免用全页 DOM 观察器改文字。
4. 自动生成首行显示 CCraft，真实 Arduino 程序除该固定注释行外与原生成结果一致。在字符串、用户注释、手动代码中放 OpenBlock，确认原内容。保留编译与完整归档兼容验收。
5. 类型检查、构建、静态资源 HTTP 字节和 MIME、VM/Blockly 字节边界通过。GUI 挂点全部定位在审核过的 GUI src，许可与版权资源仍随包分发。

本提案为只读审计结果，浏览器运行与资源制作待主控冻结后由开发和测试执行。
