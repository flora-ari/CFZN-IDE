# 游客编辑器前端提案

用户要求在登录页「返回创客平台」同一行右侧增加「游客进入」。游客进入真实编辑器，可以编辑和执行积木、导入和导出完整作品，不能把作品保存到服务器。最终契约已由主控冻结在 `docs/api-contract.md` 的「游客编辑入口」章节。

## 入口和模式生命周期

登录页用一行左右布局呈现「返回创客平台」和「游客进入」。后者是具有键盘焦点和明确名称的入口，导航到固定的 `/?mode=guest`。在登录请求提交期间禁用，防止同页出现两种跳转。

游客是认证构建内的显式模式。当前顶层 URL 中精确的 `mode=guest` 是模式来源。`main.tsx` 在调用 `resolveIdeUser` 前读取该参数，命中后直接创建真实的 `<App guest />` 和 OpenBlock iframe。模式读取使用小型共用函数，由入口和项目 API 采用一致的规则。原有 `VITE_IDE_AUTH=false` 的匿名本地版本继续使用自己的模式。`account` 为空不能单独作为游客判断依据，否则现有本地项目接口会被错误地套用游客规则。

同标签刷新保留 URL，因此仍进入游客模式。参数只表达本标签的进入方式，作品内容继续由当前编辑器持有。刷新和离开时沿用原有脏作品保护。作品内容持久化、草稿恢复及自动保存属于另外的能力。

账号密码登录和 SSO 兑换成功后沿用 `location.replace('/')`，新的根入口没有游客参数，正常进入账号模式。登录或兑换失败时留在对应页面，用户可通过「游客进入」返回游客入口。已有登录 Cookie 的用户显式选择游客时，编辑器也使用游客模式，不进行 `me`、`refresh` 或 `logout`，不绑定账号。浏览器中其他标签的登录状态继续由已有认证机制管理。

游客页不订阅 `watchIdeSession` 或 `subscribeIdeSession`，其他标签登录、退出或换号不会把正在编辑的游客页自动升级或重载。成功登录的标签在导航后使用账号模式，原来的其他游客标签继续使用游客模式。模式在文档启动时从顶层 URL 读出，运行中的游客页面通过切换账号 Cookie 不能获得作品写入能力。

URL 参数是公开编辑器的进入方式，不能作为账号身份或服务端授权证据。游客模式无需浏览器存储许可。

## 编辑器与项目操作

`App` 明确接收 `guest`。游客保留新建、导入、导出、原生标题编辑、积木工作区及素材编辑。`.ob` 和 `.sb3` 输入继续经过现有大小检查、归档校验及事务恢复，导入后标为未保存。导出继续下载完整 `.ob` 文件，保留积木、素材和已有侧车元数据。导出不发送 `MARK_SAVED`，因此作品的未保存状态和离开确认继续有效。

游客显示原生账号位置的「游客」状态，菜单提供「登录创客账号」。进入登录页前通过父页取得当前脏态并确认未保存更改，取消后继续编辑。确认离开后设置现有的允许导航状态，避免再次出现离开提示。任何游客提示应说明「登录后可保存到账号，可使用导出保存在本机」。显示登录入口时，不自动切换正在编辑的工作区。

游客的服务器项目列表、读取、创建、覆盖、重命名、删除和批量操作统一禁用。原生「项目」和「保存」显示禁用状态并提供相应说明，避免显示具有实际服务器含义的空项目列表。新建、导入和导出独立可用，不能通过复用 `documentActionsDisabled=true` 一并禁用本地操作。

主控确定的最小视图扩展是在 `AccountToolbarState` 增加可选的 `guest?: boolean`。父页游客时发送名字为「游客」、`guest:true` 的工具栏账号视图，继续携带已有的忙碌状态字段。校验器只接受布尔值。原生菜单在游客分支渲染「登录创客账号」，通过父页操作流程完成脏态确认及跳转 `/login`。账号菜单的失效、换号与固件操作维持各自分支。

原生渲染和 `canRequest` 一同更新，游客下拒绝 `projects` 和 `save`，保留 `new`、`import` 和 `export`。父页的 `toolbarAction`、`saveProject`、列表和批量回调同样检查模式，处理直接传来的消息或未来新增调用路径。原生 GUI 已配置 `canSave:false`，重复文件菜单已经通过现有挂点删除，应沿用这些路径。

父页与 iframe 内的 `installSaveShortcut` 都保留。Ctrl+S 和 macOS 的 Command+S 在游客下仍被拦截，停止浏览器保存网页动作，也不调用项目 API。禁用状态提供清楚说明。既有保存事件或原生菜单路径到达父页时，父页可显示游客提示。匹配快捷键时的输入失焦提交逻辑继续沿用，不能因此丢失当前标题或参数值。

`api.ts` 的统一请求函数在构造账号请求和调用 `fetch` 前拒绝游客请求，返回明确的 `GUEST_MODE` 错误。这样即便 Cookie 已登录，也不会从游客页发送账号作品的网络请求。账号模式继续使用 `ideProjectAttempt`、账号 ID 请求头及现有的过期恢复规则。游客 API 拒绝必须从同一份文档模式读取，避免组件和请求层判断不同。

`openblock.html` 的顶层访问保护继续把直接访问者导航到父入口，由父页面决定使用登录还是游客模式。如果直接访问 `/openblock.html?mode=guest`，仅把明确游客参数带到 `/?mode=guest`，普通直接访问仍导航 `/`。嵌入式真实编辑器从父页收到工具栏游客状态，可正常运行。既有同源、父窗口及协议校验继续适用于工具栏消息，游客参数不用于关闭这些校验。预览资源、内置模块、Link 和本机硬件能力不因作品存储模式而自动变更。私有模块采用其独立的存储和身份接口，若本轮要限制该功能，应由主控明确范围。

## 验收场景

| 场景 | 预期结果 |
| --- | --- |
| 登录页游客入口与键盘访问 | 两入口在同一行左右两侧，点击游客后载入真实 Blockly、舞台和素材能力 |
| 无登录 Cookie 游客进入并刷新 | 当前标签保持游客，作品操作正常，无账号查询或账号项目请求 |
| 保有登录 Cookie 后选择游客 | 显示游客，项目列表和保存不可用，不发送项目读取或写入请求，其他账号标签仍可继续使用 |
| 游客修改积木、标题、造型或声音并导出重导入 | 完整内容可恢复，导出后仍保持当前实际脏态，替换和离开时使用已有确认 |
| 点击保存、父页 Ctrl+S、iframe Ctrl+S 及原生保存消息 | 无 POST、PUT、PATCH、DELETE 或项目列表请求，无浏览器保存网页动作，无 `MARK_SAVED` |
| 游客登录失败、登录成功和 SSO 成功 | 失败后仍可进入游客，成功跳转后使用账号模式并可手动保存 |
| 另一标签登录、退出或换号 | 游客页面继续编辑和导出，不自动取得新账号项目能力 |
| 直接访问 `/openblock.html` | 导航父入口，并根据本标签模式进入游客或账号流程 |
| 未开启认证的原有本地版本 | 原有本地项目保存、列表与快捷键行为继续可用 |

本文件只完成设计核对，没有修改产品代码或执行浏览器测试。
