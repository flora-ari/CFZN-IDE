# 连接面板仅保留本机目录

2026-11-24。最小前端删减提案；本次用户要求覆盖此前“默认浏览器来源”规则，待主控冻结后实施。

## 最小修改

当前 [连接视图](../../apps/web/src/connection-modal.ts) 渲染来源切换和整块浏览器授权说明；[Panel](../../apps/web/src/serial-device-panel.ts) 与 [SerialSources](../../apps/web/src/local-serial.ts#L290) 都按浏览器支持情况初始化来源。只删按钮会让已隐藏的 browser 来源继续决定刷新和列表，因此要同步收敛展示状态。

- **固定本机目录。** Panel 初始化固定 local，同步 sources.setSource('local')；面板打开、刷新和重开都走现有 refreshLocal，不自动切回 browser。删除“浏览器串口”切换按钮、首次授权说明、整个“连接新设备”区域、浏览器空列表/授权错误展示及“切换来源”提示。“本机直连”不再作为可切换的按钮，可作静态区域名称，避免保留单选假控件。
- **保留现有本机功能。** 本机服务状态、重新检测/刷新、真实 OS 目录、五列、每行偏好和最右连接/断开/切换/应用均复用现有实现。列顺序仍为“设备名称｜端口｜波特率｜状态｜操作”。空列表、离线、旧服务需更新及操作占用分别如实显示；刷新不打开串口。标题/关闭固定、正文滚动和窄屏操作右对齐保持已验收布局。
- **正常浏览器候选不显示。** panel.rows 只取本机设备，加上确实仍被 HardwareSession 持有的旧浏览器活动行。未连接的已授权浏览器对象即使留在底层缓存，也不进入面板，不和 OS 行合并或推测 COM 映射。不在面板生命周期调用 getPorts('browser') 或 requestPort；本机服务不可用也不自动恢复浏览器入口。
- **旧活动句柄可见且可释放。** 旧浏览器行包含 open、closing、待释放/结果未知等仍持有状态，显示其真实名称、“浏览器授权端口”、实际速率和状态，保留最右“断开/重试断开”；可用简短“保留的已有连接”标识，不重新呈现授权流程。该行只供查看与释放，不提供新连接、保存偏好或应用设置入口；其原偏好仍保留。打开面板、改变显示来源和刷新不得关闭它；用户显式断开或按既有事务切到本机设备，确认释放后旧行才消失。关闭失败继续显示占用并阻止再次打开，不能隐藏所有权。

底层 Web Serial、SerialSources 缓存、HardwareSession 唯一 reader/writer、NativeSerialSocket、VM API 和终端兼容继续保留；没有必要批量删除 choose/connectNewDevice 等内部兼容方法。所有操作沿用忙、模式/协议、编译烧录和关闭确认守卫；已运行的作业/终端不会因 UI 删减被强行停止。HTTP、后端、依赖、作品格式及 VM/Blockly 字节均无需变化。

## 聚焦验收

1. 支持/不支持 Web Serial 都固定显示本机目录；DOM 不再出现来源切换按钮、首次授权说明或“连接新设备”区域。打开/刷新/重开只请求本机目录，不调用浏览器授权或浏览器枚举。
2. 本机行与五列操作正常，普通浏览器缓存行不重复出现；逐行波特率独立、按钮位于最右，既有视口与滚动布局通过。
3. 注入一个旧浏览器活动句柄：开关面板和刷新不关闭；本机服务离线时仍可按守卫断开；关闭失败留行、保留占用，成功后移除。未活动浏览器行始终不显示，切本机连接仍先确认释放。
4. 编译/烧录、协议占用和待释放状态仍拦截冲突操作；上传前释放/终态后恢复及 VM 字节核对沿用原验证规则。

本轮仅新增本设计；不实施、不启动服务，不操作浏览器或实体串口。主控只需更新前端来源/入口规则，零 API 变更。
