# 自定义模块扩展前端设计

本文件是前端提案。接口字段、身份解析及存储行为以主控冻结的 `docs/api-contract.md` 为准。

## 入口与操作

- 在扩展库的「模块扩展」页，把「自定义模块扩展」按钮放在 `apps/web/src/extensions/library.ts` 的 `cfzn-extension-status` 当前主控状态旁。没有主控时也可打开工厂、创建和预览。加载到作品时才检查主控兼容性。主控扩展、舞台扩展与独立选择主控窗口沿用现有入口。
- 进入工厂后显示当前身份下的模块。列表支持创建、查看详情、以现有模块为草稿创建新版本、隐藏和添加到作品。创建成功后更新列表，可以回到模块库直接添加。提交失败则保留输入，给出可重试的反馈。网络失败与空列表分别显示。
- 工厂在原扩展库窗口中使用独立视图。回到扩展库恢复分类、筛选和焦点；提交期间禁用重复操作。可按键盘顺序访问名称、主控、参数及代码编辑器。离开尚未保存的草稿时允许继续编辑或放弃草稿。浏览、预览、保存和隐藏模块本身不属于作品改动。添加模块成功后走现有作品变更通知和恢复机制。
- 编辑流程由模块信息、积木列表、参数配置、真实积木预览、Arduino 代码模板组成。模块信息包括名称、说明、版本标签、分类、颜色和兼容主控。积木编辑包括名称、形状、参数顺序、影子默认值和下拉选项。优先交付语句、数值或字符串报告、布尔报告，事件帽须先验证 Arduino 的顶层生成语义再开放。内置 Arduino 开始帽仍可带自定义语句积木。

## 从积木到运行时

1. 工厂数据以对象表达积木标签、连接类型、有序参数与模板。持久化 ID 使用服务端分配的 `custom` 加 32 位十六进制字符串。积木 opcode 与分类 ID 从模块 ID 派生，参数名、模板引用和标签占位符在保存前校验。模块标题的改动不决定 opcode。UI 可生成新草稿标识，正式保存返回的服务端 ID 是运行时依据。
2. `openblock.ts` 的 `attachPaletteSearch` 已取得 `this.ScratchBlocks`。同一挂点可把实例交给工厂，建立无 VM 监听的只读预览工作区。预览在自己的临时命名空间定义积木，离开时释放工作区及临时定义。积木形状、参数连接、默认影子和设备下拉使用与正式安装相同的构造逻辑。未选主控时按草稿所选兼容板预览或显示引脚占位。
3. 注册器将定义编译为 `defineBlocks` 与 `defineGenerators` 以及 XML 工具箱。使用固定 API `Blockly.Blocks[opcode]`、`Blockly.Arduino[opcode]`、`block.getFieldValue` 和 `Blockly.Arduino.valueToCode`。用 XML DOM 构造工具箱，HTML 文本走 React 文本节点，命名字段走有限白名单。为 Blockly 的解释实例传入可信 TypeScript 闭包。用户字符串始终是 C++ 源文本或参数模板，禁用 `eval`、`new Function`、可执行模块 URL 或同源动态脚本加载。
4. Arduino 生成器模板允许正文和公共声明。语句返回字符串并正确结束语句行，报告积木返回 `[表达式, 优先级]`。参数取值区分下拉字段和 Blockly 子积木的生成代码。解析模板时检查引用存在，使用受限的插值并限制定义体积与生成输出，拒绝递归模板。`includes_`、`definitions_`、`setups_` 等现有代码阶段由适配器写入，不把生成器对象交给用户文本。公共片段使用按模块和片段派生的键去重，积木程序不同参数的实例仍分别生成正文。旧工厂允许自由编写 JS 生成器，本轮等效覆盖的是代码模板和接口数据，复杂自由脚本须按模板重新表达。
5. `ExtensionAdapter` 统一用内置目录和私有模块目录查找条目。自定义条目仍走 `transaction`、`deviceReady`、`DEVICE_EXTENSION_ADDED`、`runtime.addDeviceExtension`、工作区重建和工具箱确认。`ToolboxPresentation.hasModule`、`compose`、`unsupportedOpcodes` 使用已装入项目的条目描述。编程模式继续把上传积木呈现为不可用，通过 `stage-execution` 拦截执行。兼容主控切换时检查所有已有自定义积木的设备字段值，任何已使用引脚在目标板不可用时按现有机制拒绝切换。在新建、加载与失败回滚时清理旧目录和积木注册，使同一页跨作品的工具箱状态正确。

兼容主控来自当前 Arduino 上传链路支持的板卡，使用 `normalizeDeviceId` 处理旧拼写。设备下拉键可采用旧工厂的数字输出、数字输入和模拟输入三项。实际装入时从当前主控解析选项。预览和新积木可选择有效默认项，加载作品时要保留既有合法参数值。

## 私有模块与作品恢复

- 以服务端同源 API 为准，列表、按 ID 读取、创建和隐藏均在当前身份下完成。前端沿用 `apps/web/src/api.ts` 的错误处理方式。用户身份不从 URL、模块定义或作品解析，也不由前端提交可伪造的所有权字段。匿名本地时的身份边界与项目沿用主控契约，后续接入统一用户时模块 UI 依赖相同 API。
- 新定义拥有新 ID。当前作品或旧作品中的 ID 精确引用原定义。隐藏操作从工厂目录撤下该定义，同一所有者可继续按 ID 恢复以前的作品。作品仍使用 `project.json.deviceExtensions` 中的 ID 和完整 `.ob` 归档。用户导出的作品包含依赖 ID，私有模块源码、生成模板及图标资源由私有 API 提供。这也意味着不同身份即使拿到 `.ob` 归档，仍须有相应模块读取资格才能恢复。可在导出或打开失败的位置说明具体依赖。
- 导入、打开和恢复前先读取 `project.json` 并解析所有自定义 ID，从当前身份的私有 API 取得具体定义与兼容性。验证成功后再停止运行并切换作品。失效身份、未授权、缺定义、离线服务和不兼容板卡都给出清楚失败原因，保留当前作品。预取在外部适配层完成，反序列化按同一次预校验快照安装模块，加载回滚使用原项目快照，避免在中途再次取数。原生启动对象和历史无私有模块归档可直接沿用当前路径。
- 私有数据仅用于当前身份与当前编辑器实例。模块 API 使用 `no-store`，身份变化后清空模块目录和预取结果。已打开作品为事务回滚持有的内存对象不能作为另一身份读取作品时的授权证据。删除作品中的模块仍走已有检查，已被积木、影子或模块依赖使用的条目不能直接移除。

## 验收

| 场景 | 观察结果 |
| --- | --- |
| 在模块扩展页用键盘打开、关闭工厂，及没有主控时创建 | 按钮紧邻当前主控状态，关闭后焦点和筛选恢复。草稿可保存，与现有作品脏状态独立 |
| 创建语句、布尔与报告积木并设置默认值和设备下拉，刷新后复核 | 真实 Blockly 预览与新工具箱中的形状、参数顺序、默认值和下拉一致。保存失败保留草稿，跨身份列表不串数据 |
| 在兼容 ESP32 或 Uno 的上传模式添加自定义模块，拖出语句到 Arduino 开始，嵌套报告或布尔积木，更改输入 | 现有代码面板立即生成预期 Arduino C++，代码包含对应参数与公共片段，作品变为未保存。切到编程模式后遵守现有上传积木的禁用规则 |
| 加入后保存，刷新或另开同身份页；创建新版并隐藏旧条目 | 旧作品继续按原 ID 恢复相同积木、参数、连线、代码、造型和声音，新作品可选用新版。普通项目与内置模块保存、加载和切板行为正常 |
| 另一身份打开带私有模块 ID 的作品，或以模拟失败响应重试加载 | 清楚显示依赖无法读取，原作品、设备、积木、当前保存状态都保留。直接猜测 ID 访问服务端资源由权限测试覆盖 |
| 空模板、无效占位、非法 opcode、特殊字符和伪造 XML 或 JS 字符串 | 校验反馈定位字段，特殊字符只进入相应文本或 XML 数据字段，工厂或 API 控制范围内的用户 JS 不运行。异常注册路径触发事务回滚 |
| 切换主控并验证设备引脚 | 兼容板列表正确。目标板支持既有引脚时可切换，不支持时在变更前阻止。通过独立终端或编译链路验收时注明是否连接实体设备 |

验收使用开发页及生产构建。对原生 VM 模块按既有检查逐模块对照上游，确认改动覆盖仅在 GUI 挂点与外部适配层。设计审查未运行产品代码、浏览器测试、编译或实机烧录。
