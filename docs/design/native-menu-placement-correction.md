# 原生 MenuBar 位置修正

主控依据用户 2026-11-06 的位置纠正冻结；Astra Ultra 只读源码复核已完成。此记录替代先前把项目操作放进 alerts 容器的布局提案，最终要求以 `../api-contract.md` 为准。

## 用户要求与实现边界

六按钮及保存状态直接进入原生蓝色 MenuBar 同一行；删除菜单下方新增区域，移除原生“文件”菜单。外层 app-bar 不恢复。项目操作、保存状态和父子消息沿用已经对齐和验证的实现，后端不改。

## 固定源码核对

固定 GUI 版本为 `0.1.0-prerelease.20250611102354`。原 MenuBar 根 Box 的直接 children 是 mainMenu、fileMenu（标题区）、tailMenu。工具组插入标题区之后、tailMenu 之前，作为该根节点的直接子元素；保留原 containerRef，用专属 data 属性限制布局样式范围。相关插入片段唯一匹配，仍通过前端准备脚本的固定版本/源片段校验应用。

原生文件下拉由 `canManageFiles` 与 `fileMenuOpen` 的独立分支渲染。删除该分支的显示，不按共享 menuBarItem/hoverable/active 类删除。标题所在 fileMenu 容器保留，其他原生菜单、设备/连接及编程模式保留。原生标题的窄屏紧凑行为沿用现状。

移除 alerts 挂载、body 间距标记以及高度测量/CSS 变量。原蓝色 MenuBar 保持 3rem；标签页紧接其后。桌面六按钮与状态均完整落在 MenuBar 内。窄屏采用工具组内单行滚动，不对整个 MenuBar 设置会裁切下拉菜单的 overflow。

## 聚焦验收

核对 DOM 父节点和几何位置、原生文件入口消失而其他菜单可用、无第二行或残留预留高度、桌面/窄屏截图、实际导入/保存/导出及抽屉操作、原生告警与扩展入口。消息和保存逻辑不变时复用上轮完整回归结果，不重新执行无关硬件/API/扩展矩阵。
