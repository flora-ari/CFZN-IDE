## 与 CFZN v0.6/v0.7 的差距

| 能力 | CFZN 现状与需要补齐的行为 |
| --- | --- |
| 入口与分类 | 已有原生加扩展入口内的舞台/主控/模块，以及顶栏原生主控入口。两处主控共享 20 条注册目录和筛选。现有三种模块类型已经真实可用。桌面版的目录更大，套件、扩展板、通信、显示等需要对应的 CFZN 条目才有分类意义。 |
| 当前模式 | 当前广义入口仅在打开时读取模式决定初始分区。主控结果未按登记的 `programMode` 过滤，六模块也未在卡片上区分编程可预览与上传可用。v0.5 已允许两种模式下添加兼容模块，并在编程工具箱禁用其上传积木。这里缺少的是目录可见性和卡片反馈。 |
| 当前主控 | 已有真实兼容矩阵、右上角状态和可选的“支持当前主控”，禁用不兼容的添加。先选主控再浏览时，桌面直接投影出当前可用模块。CFZN 保留无板浏览和全部目录，已有筛选可提供兼容视图。需要补齐的是从空结果辨别未选主控、当前主控无兼容项和其他筛选造成的未命中。 |
| 搜索 | 原生 `Library.getFilteredData` 对已预筛列表搜索名称、`tags`。缺口是可见的本地化描述和已登记的真实编号。v0.7 工具箱里的积木文字搜索负责已加载的真实积木，继续作为独立入口。 |
| 已加载 | 已有 v0.7 “已加载”勾选和 v0.6 当前主控/已添加、独立移除。缺口是“全部”列表内可扫读的已添加分组，以及筛选后明确区分已添加和其余结果。 |

## 建议冻结的交互与判据

### 入口、类型、兼容与模式

- 保留两个原生入口。通用扩展入口允许在舞台、主控和模块间导航。建议编程模式仍从舞台开始，上传模式未选板从主控开始，上传模式有板从模块开始。顶栏主控入口始终进入主控扩展视图。两个主控视图使用同一有序可见投影和同一筛选判据。
- 主控候选来自原生注册目录，排除空主控命令和 `hide:true`，保留真实禁用项及已有类型。模块候选来自内置目录。类型从该分区完整可信目录生成，搜索和其他过滤不让选项凭空消失。未知类型在“全部”与查询中保留。现有代表条目为主控板、人体红外等传感器、有源蜂鸣器等执行器、积木注释等功能模块。
- 模块兼容仅按 `supportsModule(entry, currentDeviceId)` 判断，继续复用已登记别名归一化。无板时保留模块目录与灰色“未选择主控板”，禁用并清除“支持当前主控”，提供“选择主控”。例如 Arduino Uno 与 FireBeetle ESP32-E 支持现有六模块，Micro:bit 在 CFZN 目录中支持零个。选择当前主控后，开启该筛选即可隐藏不支持项。兼容、模式用途、已加载与硬件连接各有自己的含义。
- 候选模式字段来自 CFZN 可信元数据。主控读取注册项 `programMode`，将原生 `realtime/upload` 映射到编程/上传筛选。本仓库 Uno、Nano、Mega 2560 的注册元数据含两模式，普通 ESP32、ESP32-S3、爱集特 ESP32-S3、FireBeetle ESP32-E 的元数据只含上传。缺失元数据仍在“全部”显示，不赋予当前模式命中。元数据表示目录标注的硬件积木模式，Uno 之外的板是否能走 CFZN 实时协议或本机烧录仍以已有运行能力为准。
- 模块的模式标记来自实际注册的积木执行/生成实现。本期六模块均有 Arduino 生成器且缺少实时原语，可在编程模式预览和添加，卡片明确显示“积木仅上传模式”。即使当前板支持该模块，也不能显示“编程可用”。建议主控与模块各提供同一含义的“仅当前模式”可选筛选，默认关闭。打开时按实际当前模式显示有登记实现的条目。编程模式下六模块全部排除属于有意义的空态，应说明当前模块用于上传，并可清除该筛选以恢复浏览。
- 推荐“支持当前主控”继续默认关闭，切换主控时重算而不隐式修改作品。若主控选择更接近桌面的默认兼容视图，可限定为有主控时首次打开模块分区默认开启，并保留显式关闭、无板预览和“清除筛选”回到完整目录。两种默认只能选定一种。模式筛选从既有运行时快照派生，不触发切模式、重载板、申请串口或改变添加规则。

### 搜索、已加载与空态

- 继续使用原生搜索框。主控与模块按当前 locale 的名称、说明、目录明确提供的 SKU 及原有 `tags` 做大小写不敏感子串匹配。名称/描述若为 React Intl 元素，按既有渲染消息解析，通过同一语言快照生成可搜索文本。空字段跳过。现有内置模块未提供 SKU，只在有可信 SKU 的目录项上启用编号匹配。字段内命中即可，避免字符串拼接造成跨字段假命中，类型与状态筛选仍保留。舞台扩展沿用原生搜索规则。
- 计算顺序为完整目录 → 原生可见项 → 类型 ∩ 当前主控兼容 ∩ 当前模式 ∩ 已加载 ∩ 搜索 → 分组。类型和已加载继续按分区记忆，建议模式筛选同样按分区记忆并与两个主控入口共享。类型、模式、已加载和兼容变化时保留查询，切大分区保留既有原生清查询行为。清除筛选只重置当前分区控件和查询，回到该分区完整目录。
- 主控状态取 `adapter.currentDevice()`，以规范 ID 判定。主控“全部”保留原生顺序和“当前主控”卡片标记。模块取 `adapter.loaded()`，成功添加后立即按提交结果更新，项目中有无该模块积木不影响此判据。按筛选后的同一组结果分为“已添加”和“未添加”，组内沿原目录顺序，每张卡出现一次。仅在有实际结果时渲染对应标题，勾选“已加载”只剩已添加组。舞台继续读取现有 VM `isExtensionLoaded`，一并保留 v0.7 勾选筛选。
- 当前主控文本在结果区外保留，允许当前板因筛选从网格消失，清除筛选即可找回卡片。无结果时按实际条件提示。无板提示引导选板，有板但没有任何兼容目录项时可查看全部，模式筛选造成排空时说明当前模式和可切回查看全部，单纯未命中时沿现有清除筛选入口。空结果、事务忙和加载失败分别呈现。
- 筛选、分组、焦点、locale 及打开关闭只改变视图。真实添加、移除或换板仍走现有事务，一次成功编辑只加一次 `editVersion`。重复点击、拦截、失败或取消确认零提交，现有 dirty 原样保留。移除入口继续为独立键盘目标，移动分组或被筛掉时将焦点还给同卡、同组下一项或当前分区筛选控件。

### 集成范围

在 `apps/web/src/extensions/library.ts` 复用单一渲染器和既有 adapter 订阅，`catalog.ts` 只补可信的模块模式元数据或从已有注册信息派生。卡片状态、兼容、当前模式筛选和分组作为同一快照派生，加载中的候选保持原已提交状态。原生 Library 对 CFZN 硬件实例可加精确可选的搜索与结果分组挂点。让原生搜索过滤后的结果直接驱动分组和空态，避免第二套查询状态或查询判定。使用注册 ID 作为稳定卡片键，搜索描述通过原生 Intl，分组标题以普通 OpenBlock 文本呈现。保留卡片右上兼容角标对齐、顶部模式控件与舞台交互。

继续复用 `selectController`、`loadModule`、`removeModule` 和 `clearController`。换板兼容时保留原模式、已有模块和积木并重绑引脚，不兼容时复用既有模块/引用/引脚拦截。若主控决定增加换板确认，仅收集用户意图并在确认后重新执行既有校验，拒绝或取消时保持原作品。保留完整归档事务、原生工具箱和实际生成/执行链路。变更在 GUI 或外部展示层，VM/Blockly 字节、后端、HTTP、归档格式和仓库依赖维持现有边界。实现使用 CFZN 自有目录与 UI，桌面专有源码、样式、图标、固件、用户扩展加载及远程仓库留在证据侧。

## 聚焦验收

1. 隔离 Vite dev 和静态 dist 分别使用实际积木区扩展按钮与顶栏主控入口。主控全目录依序比较 ID、名称及原生禁用状态，确认排除取消命令与隐藏项。对相同类型、查询、已加载、模式条件，两入口获得同一有序 ID 列表。编程下“仅当前模式”核对 Uno、Nano、Mega 2560 均有，上传专用 ESP32 系列被筛掉；关闭筛选恢复所有可见项。上传下核对上传专用板可见及原模式控件行为。
2. 按无板、Uno、Micro:bit 比较六模块的右上状态和兼容筛选结果。Uno 下验证两种模式均可添加兼容模块，编程态卡片明确上传用途，开启“仅当前模式”有准确空态；上传态同条件恢复实际模块，拖出已加载模块积木并检查生成结果。兼容与模式提示均不宣称硬件已经连接或实机验证。
3. 搜索覆盖仅说明命中、中文本地化、英文大小写、已有标签和带真实 SKU 的可信用例。若生产目录无 SKU，用聚焦单测验证该字段及缺失字段，实测结果注明来源。交叉类型、兼容、模式、已加载与搜索，检验两个模块组只含匹配的真实状态且无重复卡，清除恢复完整候选。窄屏验证搜索、状态、清除和键盘移除可达。
4. 在同一作品添加一个未使用模块，观察它从未添加组移到已添加组。勾选、清除筛选不会卸载；独立移除后按当前筛选回到未添加或空结果，焦点可继续操作。重复选择零编辑变化；添加和成功移除各提交一次。用已有块引用与不兼容换板各验证一次拒绝路径，确认卡片、工具箱与真实提交状态一致。筛选前后对照 `GET_STATE` 的 `documentId/editVersion/dirty`，归档不生成新增视图字段。
5. 构建、类型检查、浏览器错误和既有 VM/Blockly 字节检查作为本次证据。若实现只涉及目录及展示，沿用 v0.6 的完整归档/硬件事务证据，做一次真实另页打开的状态回显即可。上述场景使用隔离环境，串口权限、编译/烧录及实体外设测试不纳入本轮。

## 待主控冻结

1. 是否采用上传无板先进入主控目录，以及“支持当前主控”维持默认关闭还是首次有板进入模块分区便开启。建议采用前者入口规则和既有默认关闭。

4. 是否增加换板确认。建议本轮复用现有兼容拒绝和事务，确认步骤另由主控明确时再纳入。
